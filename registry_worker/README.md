# EJN Registry Worker

`ejn-registry-worker` performs one bounded local registry transaction from
stdin JSON and writes exactly one JSON response to stdout.  It is a separate
control-plane executable; it is not the Jupyter transport helper and never
contacts a kernel or a remote host.

The worker accepts only a normalized absolute `path` whose parent and existing
registry/lock files are owned by the current user, non-symlinked, and not
writable by group or other users.  It rejects the prior Elisp registry format
and every malformed or oversized file without rewriting it.

## Request and response

Every request contains `{"v": 1, "op": ..., "path": "/absolute/path"}`.
The registry format is bounded JSON:

```json
{"v":1,"generation":7,"entries":[
  {"key":"session-id","revision":"opaque-32-hex","data":{}}
]}
```

`revision` is generated by the worker on every create or replacement and is
never accepted from a caller.  `data` is a bounded JSON object owned by EJN's
future Elisp adapter.

Operations:

- `read`
- `create-if-absent` with `entry: {"key", "data"}`
- `replace-if-revision` with `entry` and `expected_revision`
- `upsert-if-current` with `entry` and `expected_revision` (`null` creates
  only when absent)
- `remove-if-revision` with `key` and `expected_revision`
- `prune-if-revision` with a nonempty `targets` list of
  `{key, expected_revision}`

Success is `{"v":1,"ok":true,"result":...}`.  Expected errors use
`{"v":1,"ok":false,"error":{"code":...,"message":...}}`.  `busy` means
another transaction holds the nonblocking advisory lock; callers must retry
from a bounded timer rather than wait.  `conflict` means a same-key entry
changed and has been retained.  `corrupt`, `registry-too-large`, and
`unsafe-path` never rewrite the target.

## Transaction semantics

Each invocation opens `<path>.lock`, attempts `fcntl.flock(LOCK_NB)`, then
performs the complete read-modify-write while holding that FD.  The lock is
released by the kernel when the process exits or is killed, so stale recovery
does not delete or steal a lock.  Writers use a same-directory 0600 temporary
file, file fsync, atomic replace, and directory fsync.  A failed directory
fsync reports `durability-uncertain` with `committed: true`; callers must read
again before retrying a mutation.

All EJN writers must use this executable.  Advisory locks cannot protect a
registry from external writers that ignore the lock, nor are network or remote
registry paths supported.
